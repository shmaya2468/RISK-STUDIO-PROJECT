### עדכון האתר שכבר נמצא ב-GitHub וב-Netlify

אם יצרת את מאגר GitHub בתיקייה החיצונית `RISK-STUDIO-VSCode-GitHub-Netlify`, **אל תריץ `git init` שוב** ואל תפתח מאגר חדש.

1. גבה את התיקייה הקיימת שלך במחשב, ואז החלף את תוכן תיקיית `RISK-STUDIO` בתוכן התיקייה המעודכנת מה-ZIP.
2. פתח את הטרמינל **בתיקייה החיצונית שבה כבר נמצא Git**, והריץ:

   ```powershell
   git status
   git add RISK-STUDIO
   git commit -m "Polish mobile branding and add social link preview"
   git push origin main
   ```

3. Netlify, שמחובר ל־GitHub, אמור לפרסם את העדכון אוטומטית. בדוק בעמוד **Deploys** שהפריסה הסתיימה בהצלחה.

4. בפרויקט שלך, שבו Git נמצא בתיקייה החיצונית, ההגדרות הן **Base directory: `RISK-STUDIO`** ו־**Publish directory: `dist`** ביחס ל־Base; הממשק עשוי להציג את הנתיב המשולב `RISK-STUDIO/dist` אוטומטית. אין צורך לשנות את ההגדרות אם הפריסה הקודמת כבר עובדת.

5. אחרי הפריסה, היכנס ל־`https://risk-studio.netlify.app/social-preview.png` ובדוק שהתמונה המעוצבת מופיעה. בוואטסאפ ובחלק מהרשתות תצוגת הקישור עשויה להישאר במטמון זמן מה גם אחרי השינוי. אין צורך לשנות את כתובת האתר שלך.

העדכון אינו משנה את מפתח ה־`localStorage` של היומן ואינו אמור למחוק את הנתונים השמורים בדפדפן. ובכל זאת, מומלץ להוריד גיבוי לפני כל עדכון.

## שלב 1 — לפתוח ב-VS Code

1. חלץ את קובץ ה-ZIP שהורדת.
2. פתח את **Visual Studio Code**.
3. בחר **File → Open Folder**, ובחר את התיקייה `RISK-STUDIO` (לא את `dist` בלבד).
4. כדי לצפות באתר במחשב, אפשר להתקין את תוסף **Live Server**, ללחוץ לחיצה ימנית על `dist/index.html` ולבחור **Open with Live Server**.
5. לחלופין, אם Python מותקן, הרץ בחלון Terminal בשורש הפרויקט:

   ```bash
   python -m http.server 8000 --directory dist
   ```

   ופתח בדפדפן `http://localhost:8000`.

אין צורך ב־`npm install`, בבנייה (Build) או בשירות חיצוני כדי להפעיל את האתר.

## שלב 2 — לשמור ב-GitHub מתוך VS Code

1. בסרגל VS Code בחר את סמל **Source Control** (קיצור `Ctrl+Shift+G`).
2. לחץ **Initialize Repository**.
3. לחץ על `+` ליד השינויים, וכתוב הודעת Commit, למשל `Initial RISK STUDIO website`.
4. לחץ **Commit**.
5. לחץ **Publish Branch** / **Publish to GitHub**, התחבר ל־GitHub ובחר שם למאגר, למשל `risk-studio`.
6. בחר **Private** אם אינך רוצה שקוד האתר יהיה גלוי לכולם. אפשר לפרסם אתר ציבורי ב-Netlify גם כשהמאגר פרטי, בכפוף להרשאות החיבור של Netlify.

מעתה, בכל שינוי בקוד: שמור (`Ctrl+S`), בצע Commit חדש ו־Push / Sync Changes מתוך Source Control.

## שלב 3 — לחבר Netlify ל-GitHub

1. היכנס ל־[Netlify](https://app.netlify.com/).
2. בחר **Add new project → Import an existing project**.
3. בחר **GitHub**, אשר את החיבור ובחר במאגר `risk-studio`.
4. הגדרות הפריסה כבר נמצאות בקובץ `netlify.toml`. אם Netlify מבקש אותן ידנית:

   - **Base directory:** השאר ריק אם ייבאת את התיקייה `RISK-STUDIO` עצמה; אם המאגר החיצוני כולל תיקיית `RISK-STUDIO`, השתמש ב־`RISK-STUDIO`.
   - **Build command:** השאר ריק.
   - **Publish directory:** `dist`.

5. לחץ **Publish / Deploy**. Netlify ייתן לך כתובת חדשה; לאחר מכן כל Push חדש לענף הפריסה ייצור גרסה חדשה באתר.

## חשוב מאוד — נתוני היומן במעבר ל-Netlify

היומן שומר נתונים ב־`localStorage` של **אותו דפדפן ואותה כתובת אתר**. לכן הנתונים שכבר הזנת באתר הישן *לא עוברים אוטומטית* לכתובת Netlify החדשה.

לפני המעבר:

1. פתח את עמוד המשמעת **באתר הישן**, באותו דפדפן שבו מילאת את היומן.
2. לחץ **הורד גיבוי** ושמור את קובץ ה־`.json` במחשב.
3. אחרי העלאת האתר ל־Netlify, פתח בו את עמוד המשמעת ולחץ **טען גיבוי**.
4. בחר את הקובץ ואשר שחזור — הפעולה **מחליפה** את הנתונים השמורים בדפדפן של האתר החדש.

המלצה: הורד גיבוי חדש מדי פעם. מחיקת נתוני האתר בדפדפן עשויה למחוק את היומן המקומי. אין כרגע סנכרון ענן או חשבונות משתמשים.
